## 2026-10-05 — Статика, ответ по дизайну письмом, первый коммит

- **Сайт стал статическим** (`output: "export"`, папка `out/`): итерации с заказчиком без сервера, можно выложить куда угодно. Что поменялось:
  - `proxy.ts` → страница `/` (свой корневой layout в `app/(root)`) выбирает язык в браузере: localStorage `lang` → язык браузера → `/ru/`;
  - `/api/lead` убран → формы шлют письмо напрямую из браузера через Web3Forms (`src/lib/send.ts`, ключ `NEXT_PUBLIC_WEB3FORMS_KEY`); без ключа — WhatsApp с готовым текстом;
  - каталог, акции, новинки, поиск фильтруются в браузере по query-строке (`CatalogView` — клиентский, `scope` вместо списка товаров).
- **Почему Web3Forms, а не Telegram-бот из браузера:** ключ Web3Forms публичный по замыслу — им можно только слать письма на одну почту (худший случай — спам). Токен бота в коде страницы даёт читать и писать от имени бота — так нельзя.
- **/design → «Ваш выбор»:** заказчик выбирает пресет, отмечает «нравится / поменять» по шрифтам, цветам, раскладкам, компонентам → письмо с JSON (пресет + все токены + отзыв). Без ключа — «Скачать JSON» и WhatsApp. Черновик ответа хранится в браузере.
- **Вес статики:** было 688 МБ. Ёлка генерировала тысячи планок за кадром, координаты были с 10+ знаками, ковролин — сотни тысяч сегментов кривой. Стало 150 МБ: отсечение планок за кадром, округление до 0,1, ворс через SVG `<pattern>`. Остаток — служебные RSC-файлы Next на каждую страницу.
- **Первый коммит** в собственный репозиторий `floor-engineering/`.
- **Хостинг — GitHub Pages** (решение пользователя). Pages не собирает Next сам → workflow `.github/workflows/pages.yml` собирает `out/` и публикует. Сайт в подпапке `/stepline-floors` → `basePath` из `NEXT_PUBLIC_BASE_PATH`, обычные ссылки — через `withBase()`, плюс `public/.nojekyll`. Vercel отложен: его сборка падала на загрузке Google-шрифтов в Turbopack.

## 2026-10-03 — RU/KZ/EN, оформление заказа, документы, медиа, Vercel

- **Факты из 2ГИС** (go.2gis.com/I4X3W → фирма 70000001110927997): ежедневно 10:00–19:00, район Нура, рейтинг 4,5, оплата картой/наличными/через банк/по QR. Из постов: хранение до 6 месяцев, рассрочка 12 месяцев, акции «паркет 24 000 ₸ вместо 40 000», «BlackBerry −35%», Metric Lam Chevron.
- **Оформление заказа** (`/checkout`) по образцу mirparketa, но обязательных полей минимум: имя, телефон, согласие. БИН — только для компаний, адрес — только при доставке. ИИН физлиц не спрашиваем (не нужен для заказа). Заказ получает номер `SL-ГГММДД-XXXX`.
- **Заявки** уходят в Telegram (`TELEGRAM_BOT_TOKEN/CHAT_ID`) и/или вебхук (`LEAD_WEBHOOK_URL`), всегда дублируются в лог Vercel.
- **Документы** — черновики по законам РК, реквизиты в квадратных скобках, полный текст на русском, kk/en — краткое изложение.
- **Cookies:** полоса внизу, «Только необходимые / Принять все». Метрика и GA грузятся только после согласия. Instagram и 2ГИС — по клику (фасады), без сторонних запросов до действия.
- **Поиск** выглядит как раздел: запрос остаётся в поле, чипы «где нашлось», фасеты только по найденному, пустые значения скрыты.
- **Акции** — витрина двух реальных акций + полоса «скидки до N%». **Новинки** — без отдельной витрины (решили: ту мач).
- **Медиа** по образцу greenline/gallery: 8 настоящих публикаций @stepline_astana + место под фото объектов.

## 2026-10-01 — Поворот: шаблон магазина STEPLINE по образцу mirparketa.kz

**Бриф:** «сделать прям фулпохожее» на [mirparketa.kz](https://mirparketa.kz/akczii/) — шаблон, который
дальше дорабатываем сами. Клиент — **STEPLINE** ([@stepline_astana](https://www.instagram.com/stepline_astana/)):
салон в Астане, пр. Туран 39/3, «Ламинат • SPC • Паркет, 100+ вариантов, проверенные бренды,
бесплатная доставка и хранение», WhatsApp 7 771 271 75 75. Плюс отдельный раздел «На заказ».

### Что взяли у mirparketa (структура, не пиксели)
- Шапка в три этажа: полоса с адресом и инфо-ссылками → лого, поиск, телефон/WhatsApp,
  сравнение, корзина с суммой → меню категорий с выпадающими «Вид / Цвет», справа Новинки NEW,
  Акции SALE.
- Главная: баннеры → плитки разделов и видов укладки → преимущества → «Мы рекомендуем» с
  вкладками → акции → новинки → салон → SEO-текст.
- Каталог: чипы видов, слева фильтры (цена, наличие, тип дизайна, цвет, бренд/страна, класс,
  толщина, длина, ширина, фаска, соединение, покрытие, тёплый пол, влагостойкость) со счётчиками,
  сортировка, пагинация. Фильтры — в query-строке.
- Карточка: −% / NEW / «под заказ», цена старая/новая за м², в корзину, сравнение.
- Товар: характеристики, продажа упаковками + калькулятор «м² → упаковки» с запасом на подрезку,
  «Уточнить у менеджера» в WhatsApp, предупреждение о цветопередаче, похожие.
- Корзина без аккаунта → заявка менеджеру + «отправить заказ в WhatsApp». Сравнение до 4 позиций.

### Что сознательно НЕ взяли
Попап выбора города при входе, баннер cookie на пол-экрана, «4 человека смотрят товар»,
авто-карусель, зелёные кнопки-плашки на фото. Это шум и фальшивая срочность.

### Решения
1. **Пресет «Stepline» основной**: белый салон (не чистый #fff), фирменный коричневый из логотипа,
   красный только для скидок (`--color-sale`). Geologica + Onest. Остальные 4 пресета живут в /design.
2. **Фото товаров пока нет** → «фото» = раскладка товара в его тоне (`ProductImage`). На странице
   товара подпись «схема укладки в тоне декора». Когда будет выгрузка с фото — подменить.
3. **Демо-каталог** (~75 позиций) генерируется в `src/data/products.ts`; реальные только бренды
   ламината из постов (SOHO, BlackBerry, Metric Lam). Плашка «Демо-каталог» в шапке до замены.
4. **«На заказ» — другой продукт**: свой layout без меню магазина, тема `data-theme="order"`
   (хвоя + песок, Literata). Лукбук: коллекции → плитки декоров с кодами → выбор нескольких →
   запрос. Слово «Китай» нигде не звучит — «каталоги фабрик-партнёров». Данные —
   `src/data/order-collections.ts`, формат описан в шапке файла (как переносить PDF).
5. **Факты только из профиля.** Часы работы, оплата, обмен/возврат, укладка — «уточняется».

### Открыто — спросить у STEPLINE
- Логотип в векторе (сейчас перерисован по JPEG), часы работы, почта.
- Выгрузка прайса/остатков (1С? Excel?) с фото — заменить демо-каталог.
- Способы оплаты (Kaspi, рассрочка), доставка в другие города, обмен/возврат, укладка.
- PDF-каталоги для «На заказ», сроки поставки и как считать цену.
- Куда слать заявки: CRM / Telegram-бот / почта (`/api/lead` пока пишет в лог).

## 2026-10-01 — Страница /design и четыре пресета

Пользователю понравилась идея страницы-образца, где сразу видно шрифты, цвета и остальное.
Сделали `/design` и четыре пресета одной системы, их можно переключать прямо на живом сайте.

| Пресет | Бумага | Заголовки + текст | Акцент | Для чего |
| --- | --- | --- | --- | --- |
| Дуб и тушь (основной) | светлая, тёплая | Cormorant Garamond + IBM Plex Sans | терракота | паркет, средний и высокий чек |
| Мастерская | светлая, холодная | Geologica + Golos Text | кобальт | SPC, ламинат, прорабы, B2B |
| Шоурум | тёмная | Prata + Commissioner | латунь | премиальный и модульный паркет |
| Лён | светлая, зеленоватая | Literata + Onest | мох | светлый дуб, ковролин, семьи |

Пресеты попарно различаются хотя бы по двум осям из трёх (бумага / тип заголовка / тон акцента),
иначе выбор между ними теряет смысл.

### Как устроено
- **Один источник** — `src/design/presets.ts`. Из него собирается CSS (`:root` и
  `[data-preset=…]`) и вся страница `/design`. В компонентах только `var(--…)`.
- **Переключение:** `/?preset=showroom` или выбор на `/design` — сохраняется в localStorage.
  Инлайн-скрипт в `<head>` ставит пресет до первой отрисовки, поэтому мигания нет. Пока включён
  не основной пресет, на сайте висит плашка «Пресет „…“ · Вернуть основной», чтобы черновой
  вариант не приняли за утверждённый.
- **Шрифты** не основных пресетов — `preload: false`: браузер скачивает их, только когда
  пресет включён.
- **На /design:** полоса пресетов (каждый в своих цветах), живой первый экран, шрифты с
  алфавитом и весами, шкала, цвета с HEX и контрастом WCAG к фону, доля цвета на экране,
  древесные тона и все раскладки, компоненты на **настоящих CSS-модулях сайта** (не копии),
  отступы, экспорт токенов. Клавиши 1–4 переключают пресеты.
- **Тона подбора** (светлый / натуральный / …) общие для всех пресетов: это цвет товара.

### Открыто
- Показать клиенту четыре пресета и выбрать основной (`DEFAULT_PRESET`).
- В «Шоуруме» футер получается светлым: его фон — `--color-ink`. Если пресет выберут, решить,
  оставить так или завести отдельный токен для футера.

## 2026-10-01 — Первая версия

### Бриф (от клиента, дословно по смыслу)
Разделы: общие вкладки · ламинат (палуба, английская ёлка, французская ёлка) · паркет
(палуба, ёлка, геометрический, модульный) · кварцвинил / SPC / LVT (замковый, клеевой) ·
ковролин · клей · подложка · плинтус. Плюс фильтр по цвету, названию и размеру.
Пример «как было» — parket-greenline.ru.

### Что взяли и что отвергли у Greenline
- **Взяли:** деление паркета по раскладке (английская / французская ёлка, модульный,
  геометрический). Покупатель так и думает: сначала рисунок, потом порода.
- **Отвергли:** сетку из фотокарточек категорий, карусель проектов, блок «преимущества»
  (качество / стабильность / европейский уровень). Это слова без проверяемого содержания.
  У Greenline нет фильтров — только переходы по категориям. У нас фильтр есть.

### Решения
1. **Каталог — это типографский указатель, а не сетка карточек** (Hallmark: Index-First).
   Каждый раздел — строка на линейке: название, одна строка «зачем», виды как ссылки,
   рисунок укладки справа. Как оглавление образцовой книги паркетчика.
2. **Вместо фото — раскладки, построенные геометрией** (`FloorPattern.tsx`). Ёлка, французская
   ёлка, палуба, квадраты, модули, след шпателя для клея, сечение плинтуса. Тушью в списке,
   древесными тонами в первом экране. Причина: реальных фото у клиента пока нет, а сток с
   интерьерами — главный признак шаблона. Когда появятся фото объектов, ставим их в первый
   экран, раскладки остаются иконками в списке.
3. **Подбор — таблица, не плитка.** Вкладки разделов, поиск по названию, цвет пятью
   тонами (светлый / натуральный / тёплый / тёмный / серый), размер — точные форматы из прайса,
   появляются после выбора раздела. Фильтры пишутся в адрес (`?cat=parquet&type=herringbone`) —
   менеджер может прислать клиенту готовую подборку.
4. **«Что взять к полу»** — матрица покрытие → подложка / клей / плинтус. Отвечает на
   разделы 6–8 брифа: клей, подложка и плинтус живут не сами по себе, а в связке с покрытием.
5. **Палитра:** бумага цвета светлого дуба (oklch 96.5% 0.012 80), тушь тёмного ореха,
   один акцент — терракотовый лак (oklch 50% 0.13 40), меньше 3% экрана. Никаких градиентов,
   стекла, теней.
6. **Шрифты (все с кириллицей):** Cormorant Garamond — заголовки, IBM Plex Sans — текст,
   JetBrains Mono — только размеры (600 × 100 × 15 мм), чтобы цифры стояли столбиком.
7. **Заявка** — одна форма в конце, кнопка «Узнать цену» в строке таблицы подставляет позицию
   в комментарий. API `/api/lead` пока пишет в лог.

### Открыто — спросить у клиента
- Название бренда, город, телефон, адрес шоурума, часы (сейчас прочерки, `src/content/site.ts`).
- Реальный прайс: позиции в таблице — образец структуры (`src/data/products.ts`, флаг `SAMPLE_DATA`).
- Делают ли укладку сами, есть ли выезд замерщика с образцами — шаг 2 и 4 в «Как проходит заказ».
- Куда слать заявки: CRM, Telegram-бот, почта.
- Цены на сайте показываем или «по запросу»?
- Фото реальных объектов (если есть) — для первого экрана и страниц разделов.
- «Общие вкладки» — какие именно: о компании, доставка и оплата, укладка, контакты, акции?

### Дальше
- Страница раздела (`/laminat`, `/parket`…) с тем же подбором, но шире: порода, класс,
  фаска, покрытие (лак / масло).
- Карточка товара — тоже без «карточного» вида: фото раскладки, таблица характеристик,
  калькулятор м² → упаковки.
- Калькулятор расхода (площадь + 5–10% на подрезку для палубы, больше для ёлки).
